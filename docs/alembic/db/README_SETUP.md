# Alembic Migration Setup & Verification

This document explains how to set up and verify the Alembic migrations for the FastAPI + PostgreSQL backend.

## Prerequisites

Ensure your `requirements.txt` or similar includes:

```
sqlalchemy[asyncio]>=2.0
asyncpg>=0.28
alembic>=1.13
psycopg2-binary>=2.9  # or psycopg3 if preferred
pgvector>=0.2.0
```

**Database:**
- PostgreSQL 15+
- pgvector extension should be installed on the database

## Environment Setup

Before running migrations, set the `DATABASE_URL` environment variable:

```bash
# Linux/macOS
export DATABASE_URL="postgresql+asyncpg://user:password@localhost:5432/travel_planner"

# Windows PowerShell
$env:DATABASE_URL="postgresql+asyncpg://user:password@localhost:5432/travel_planner"

# Create the database if needed (as superuser or owner):
# psql -U postgres -c "CREATE DATABASE travel_planner;"
```

## Alembic Configuration

All configuration is in `backend/alembic.ini` and `backend/alembic/env.py`.

- `env.py` reads `DATABASE_URL` from environment
- Connections use `asyncpg` driver for async support
- Migrations run in **online mode** (full async engine)

## Running Migrations

All commands are run from the `backend/` directory:

```bash
cd backend/
```

### 1. Upgrade to the latest schema

```bash
alembic upgrade head
```

Expected output:
```
INFO  [alembic.runtime.migration] Context impl PostgresqlImpl.
INFO  [alembic.runtime.migration] Will assume transactional DDL.
INFO  [alembic.runtime.migration] Running upgrade  -> 0001, initial_schema
INFO  [alembic.runtime.migration] Running upgrade 0001 -> 0002, schema_hardening
INFO  [alembic.migration] Context impl PostgresqlImpl.
INFO  [alembic.migration] Will assume transactional DDL.
```

### 2. Check current migration status

```bash
alembic current
```

Expected output:
```
0002
```

### 3. Downgrade to base (undo all migrations)

```bash
alembic downgrade base
```

Expected output:
```
INFO  [alembic.runtime.migration] Context impl PostgresqlImpl.
INFO  [alembic.runtime.migration] Will assume transactional DDL.
INFO  [alembic.runtime.migration] Running downgrade 0002 -> 0001, schema_hardening
INFO  [alembic.runtime.migration] Running downgrade 0001 -> , initial_schema
INFO  [alembic.migration] Context impl PostgresqlImpl.
INFO  [alembic.migration] Will assume transactional DDL.
```

Verify it's empty:
```bash
alembic current
```

Should return no output (or `<empty>`).

### 4. Upgrade again to verify round-trip

```bash
alembic upgrade head
```

Should see the same upgrade output as step 1.

## Full Round-Trip Verification (Recommended)

Run this script to verify the migrations work cleanly:

```bash
#!/bin/bash
set -e

echo "Step 1: Running alembic upgrade head..."
alembic upgrade head
echo "✓ Upgrade complete\n"

echo "Step 2: Checking current migration..."
alembic current
echo "✓ Current revision shown\n"

echo "Step 3: Running alembic downgrade base..."
alembic downgrade base
echo "✓ Downgrade complete\n"

echo "Step 4: Running alembic upgrade head again..."
alembic upgrade head
echo "✓ Round-trip successful!\n"

echo "Final check - current revision:"
alembic current
```

Save this as `verify_migrations.sh` and run:

```bash
chmod +x verify_migrations.sh
./verify_migrations.sh
```

## Checking the Schema

After running `alembic upgrade head`, inspect the created objects in PostgreSQL:

```sql
-- Connect to the database:
psql -U user -d travel_planner

-- List tables:
\dt

-- List indexes:
\di

-- List triggers:
SELECT * FROM information_schema.triggers WHERE trigger_schema = 'public';

-- Check extensions:
SELECT * FROM pg_extension;

-- Verify a table structure (e.g., destinations):
\d destinations
```

Expected tables:
- `users`
- `user_preferences`
- `raw_scrapes`
- `destinations`
- `tags`
- `destination_tags`
- `listings`
- `user_interactions`
- `itineraries`
- `destination_images`
- `listing_images`

Expected extensions:
- `vector` (pgvector)
- `pg_trgm` (fuzzy search)
- `pgcrypto` (UUID generation)

## Creating New Migrations

### Hand-Written Revision

For manual SQL-style migrations (not autogenerated):

```bash
alembic revision -m "descriptive message"
```

This creates a new file in `alembic/versions/` with `upgrade()` and `downgrade()` functions.

Edit the file to add your SQL using `op.execute()`, `op.create_table()`, etc.
